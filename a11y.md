# Ease of Access (Accessibility Statement)

> **Note:** Calctainer is a free, open-source tool maintained by a private person, not a commercial service. It is not in the service categories covered by Directive (EU) 2019/882 (European Accessibility Act) and no micro-enterprise or consumer-contract obligations are assumed. This statement is published voluntarily and follows the directive's Annex V structure, with the information adjusted to this situation (for example, no postal address and no regulatory complaint procedure).

## 1. Provider and contact

- Provider: private person, [dm0dev on GitHub](http://github.com/dm0dev)
- Feedback and accessibility problems: please open an issue or contribution at [github.com/dm0dev/calctainer](https://github.com/dm0dev/calctainer). Describe the problem, the view concerned, your browser and any assistive technology.

## 2. About the service

Calctainer is a browser-based capacity planner for application workloads on HyperShift / Hosted Control Plane (HCP) clusters. It runs entirely in the browser without a backend or account. Views: Workloads, Node pools, Scheduling, Quota, Findings, Savings, Assumptions, and Import / export. The interface is available in English and German and has three experience levels (Guided, Standard, Expert) over the same scenario.

## 3. Compliance status

Calctainer is **partially compliant** with WCAG 2.0 Level AA. Automated tests also apply the WCAG 2.1 A/AA rules, but the additional WCAG 2.1 criteria have not yet been assessed manually. Conformance with EN 301 549 is therefore not claimed.

How it is built: native form controls and buttons, semantic HTML, text alternatives for icons, visible focus, light and dark themes, status shown with text and not by colour alone, and the page language set and updated on language switch.

## 4. Testing

- **pa11y-ci** (axe-core and HTML_CodeSniffer, standard WCAG2AA; axe applies the WCAG 2.0 and 2.1 A/AA rules) on pull requests that change the interface.
- **Lighthouse** accessibility score, required to be at least 95.
- **Manual checks** (keyboard, VoiceOver/NVDA, visual inspection, error messages), which are needed because automated tools find only about 30–40% of issues.

On 2026-11-02, pa11y with both runners reported zero issues for the sample scenario across all seven views, all three experience modes, and both light/dark themes (42 combinations). Keyboard checks confirmed that the skip link focuses main content and cluster selection works with native button activation. This does not establish full WCAG conformance or cover every possible scenario and interaction.

## 5. Known gaps

| Criterion | Issue |
|---|---|
| 1.4.4 Resize Text | At 200% zoom, some dense table layouts may need horizontal scrolling. |
| 2.1.1 Keyboard | Custom components (e.g. chart interactions) may need review for full keyboard operability. |
| 2.4.3 Focus Order | Complex dynamic views (workload cards, pool editor) need verification of focus sequence. |
| 2.4.5 Multiple Ways | Single-page app with navigation bar only; no sitemap or search. |
| 3.2.2 On Input | Inputs trigger immediate recalculation; updates need verification for screen reader users. |
| 3.3.1 Error Identification | Errors are shown as messages, but `aria-describedby` / `aria-invalid` association may be incomplete. |
| 4.1.2 Name, Role, Value | Some custom toggles and expandable sections need verification of role and state. |
| 4.1.3 Status Messages | Status messages may not use `role="status"` or `aria-live`. |

Planned fixes in order of priority: focus management (2.4.7, 2.4.3), ARIA live regions (4.1.3).
